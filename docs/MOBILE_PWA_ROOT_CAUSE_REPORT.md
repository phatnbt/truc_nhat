# P708 · Điều tra lỗi PWA trên điện thoại

Bản kiểm thử `20261127-11`, nhánh `fix/critical-mobile-pwa-standalone` kế thừa bản sửa trực nhật đã xác minh tại `703e1fe`. Phân công, công thức hóa đơn 29–28, Rules, dự án Firebase và dữ liệu lịch sử giữ nguyên.

## Bằng chứng và nguyên nhân

| Bằng chứng | Nguyên nhân và thay đổi |

| HTTP công khai trả HTML và `sw.js` bản `20261127-4` trên cả hai hostname Firebase. GitHub Pages trả HTML bản `20261127-7`. Lần deploy Firebase gần nhất trên GitHub Actions là commit `c48d6ec`. | Các bản vá mới nằm trên GitHub nhưng chưa được phát hành đồng đều. Bổ sung metadata commit/release và đối chiếu byte của tài nguyên phát hành trong workflow. [Lần deploy Firebase](https://github.com/phatnbt/truc_nhat/actions/runs/45864702871) |

Firebase khuyến nghị redirect dùng helper cùng origin hoặc một phương án được hỗ trợ. Giữ redirect trong origin đã cấu hình và dùng popup có thao tác người dùng trên origin khác. Bản mới cache theo URL hoàn chỉnh, chỉ can thiệp khởi động tại đường dẫn ứng dụng, kiểm release của HTML trước khi worker chuyển sang trạng thái chờ. |

Logic lấy lại dữ liệu nằm ở handler kết nối và mốc 30 giây ẩn giao diện. Engine hiện xử lý các tín hiệu resume và đọc lại phòng có gộp request trùng, giữ listener hiện tại khi còn hoạt động. |
| Mã cập nhật cũ nhìn modal và bản nháp, sau đó reload trên mọi `controllerchange` do chính nút cập nhật đăng ký. | Giao dịch đang chờ có thể tồn tại sau khi modal đóng hoặc ở tác vụ khác. Nếu cache thiếu, worker chỉ chấp nhận tải lại từ server có cùng release. |

Các ca trên xác định lỗi trong ứng dụng hoặc triển khai. Cần báo cáo từ iPhone/Android đang gặp lỗi để kết luận trình tự cụ thể trên thiết bị đó. Emulator xác minh Auth, quyền và giao dịch dưới dữ liệu tổng hợp. Nó không tái hiện cookie, cửa sổ OAuth hay việc hệ điều hành suspend của ứng dụng đã cài.

## Đối chiếu nền tảng

- Firebase JS SDK và Quickstart hỗ trợ popup và redirect. Bản redirect cần kết quả xử lý sau navigation. Helper cùng origin tránh phụ thuộc vào lưu trữ bên thứ ba. Đổi authDomain của `web.app` cũng cần xác nhận OAuth redirect URI và authorized domains, ngoài việc endpoint handler trả HTTP 200. Tính năng popup iOS có đường triển khai riêng trong SDK và đã có báo cáo lỗi từ Home Screen. [Quickstart](https://github.com/firebase/quickstart-js#auth) · [SDK popup](https://github.com/firebase/firebase-js-sdk/blob/main/packages/auth/src/platform_browser/util/popup.ts) · [Firebase issue #7273](https://github.com/firebase/firebase-js-sdk/issues/7273)
- Firebase quản lý thứ tự persistence của Auth. Pending redirect dùng sessionStorage riêng. WebKit cho biết từ iOS 17.2 việc thêm web app có thể sao chép cookie ban đầu, còn IndexedDB và Web Storage nằm trong môi trường riêng. Phiên Firebase từ Safari vì thế không được giả định có sẵn trong app đã cài. [Firebase persistence](https://firebase.google.com/docs/auth/web/auth-state-persistence) · [SDK redirect resolver](https://github.com/firebase/firebase-js-sdk/blob/main/packages/auth/src/platform_browser/popup_redirect.ts) · [WebKit 17.2](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/)
- WebKit có thể hủy giao dịch IndexedDB lúc suspend. SDK có bản sửa cụ thể để kết nối lại IndexedDB on demand cho popup trên iOS/iPadOS. Cần đối chiếu lỗi thiết bị và phiên bản SDK trước khi gán nguyên nhân. localForage, idb và Dexie vẫn phụ thuộc cơ chế lưu trữ của WebKit. Không thêm thư viện cho bản này. [WebKit #202705](https://bugs.webkit.org/show_bug.cgi?id=202705) · [Firebase PR #10325](https://github.com/firebase/firebase-js-sdk/pull/10325) · [localForage](https://github.com/localForage/localForage) · [idb](https://github.com/jakearchibald/idb#transaction-lifetime) · [Dexie](https://dexie.org/docs/Dexie/Dexie.transaction%28%29)
- Firestore dùng metadata để phân biệt snapshot cache và pending writes. P708 giữ Firestore memory cache và dùng cơ chế persistence của Auth riêng. Các ứng dụng mở ngoại tuyến không thể xác minh quyền, nên P708 hiển thị chế độ khôi phục/ngoại tuyến và gửi thao tác trực tuyến. [Firestore offline](https://firebase.google.com/docs/firestore/manage-data/enable-offline) · [Firestore listeners](https://firebase.google.com/docs/firestore/query-data/listen)
- Workbox giải thích worker chờ, kiểm cache theo revision và cập nhật có chủ đích. PWACompat xử lý tương thích giao diện manifest. PWABuilder cho iOS dùng lớp bọc native khác với Home Screen. Playwright chạy WebKit để kiểm logic và giao diện, còn iOS Home Screen cần thiết bị. [Workbox](https://developer.chrome.com/docs/workbox/handling-service-worker-updates) · [PWACompat](https://github.com/GoogleChromeLabs/pwacompat) · [PWABuilder iOS](https://github.com/pwa-builder/pwabuilder-ios-app-store) · [Playwright browsers](https://playwright.dev/docs/browsers#webkit)
